## 1. サービス概要

- このサービスはどんなサービスか
  - 資産管理＋シュミレータアプリ
  - 過去と現在の資産を一元管理し、推移を把握できる
  - 現在の資産から、投資や積立を行った場合の将来資産を可視化する

- 誰の、どんな課題を、どう解決するか
  - 投資に興味を持てるようになる  
  株価の上昇率などを数字ではなく、グラフで可視化することにより、投資に興味を持つ一要因になれる。
  - 資産管理をゲーム感覚で行えるようになる  
  
    

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情
投資を始めようと考え、投資周りの情報を調べ始めた時、投資そのものに興味を持てるような“ワクワクする情報”がほとんど存在しないと感じた。  
存在するサイトは、超初心者向けの「積立だけを紹介するサイト」と、中級者以上向けの「株価要因を深掘りするサイト」の両極端しかなかった。

この経験から投資自体に興味を持てるサイトを作りたいと考えました。

---

### 2-2. なぜそれが「気になった」のか
投資は「難しそう」「自分には関係ない」と感じた瞬間に、興味を失ってしまう人が多い。  
情報は溢れているのに、投資そのものを“面白い”“やってみたい”と思える入り口がほとんど存在していない。
だからこそ、投資をもっと身近に感じられる体験が必要だと考えた。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと
投資を始めようとしても、「実際に何年後に資産がどう増えるのか」という未来のイメージが掴めないままでは、一歩を踏み出しづらい。

---

### 3-2. 本当に解決したい課題は何か

投資の未来を具体的に思い描けるようにし、投資そのものに興味を持てる状態をつくる。
未来の資産が「視覚的に理解できる」「自分の行動で変化する」と感じられることで、投資が難しいものではなく、身近で前向きな選択肢になる。

---

### 4-2. 自分とユーザーの距離
- 過去の自分

- なぜその距離感なのか理由を書いてください。  
投資を始める前の人を想定しているため。
また、私自身投資を始めるにあたり、どんな投資をすればよいかの目標があやふやで足踏みしていた経験があるため。

### 4-3. 実際に使われる可能性について(需要・存在確認)

- まず最初に使ってくれそうな人は誰か？  
投資初学者
- その人は、どんな場面でこのアプリを思い出すか？  
「投資を始めたら、実際にどれくらい資産が増えるのか知りたい」と感じた瞬間。
現在の株価上昇率や積立額から、自分の目標額（例：家の頭金など）に到達するまでの未来をシミュレーションしたくなった時。
- 今の生活の中で、代わりに使っているものは何か？
  - 証券会社のシュミレータ
  - 資産管理アプリ
- それを置き換えてまで使う理由はあるか？
  - 既存のシミュレーターと資産管理アプリは基本的に独立しており、「自分の資産を起点にした未来シミュレーション」がしづらい。
  - 銀行口座や証券口座との連携が不要で、投資初学者でも“気軽に未来を試せる”点が強み。
（投資初学者はそもそも口座を開設していないケースが多く、既存アプリよりも使い始めやすい。）


## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

このサービスは、ユーザーがどのような状況・きっかけで
「使ってみよう」と思い、利用を始めるサービスでしょうか？

また、一度使って終わりではなく、
**「なぜ・どのように使い続けてもらえるのか」**
までイメージできているかを考えてみてください。

- どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか

また、「家の頭金まであとどれくらい必要なんだろう？」
等、未来のイメージが掴めずに不安を感じた瞬間に、このサービスを思い出す。
- 最初の一歩（登録・導入）で、ユーザーは何をする必要があるか

- 利用を続ける理由は何か？（習慣・必要性・価値）
未来の資産が“自分の行動で変化する”ことが実感できる。投資を“難しいもの”ではなく“育てる楽しさがあるもの”に変える体験が得られる。


## 5. 既存サービス・競合調査

（個人向け家計簿・資産管理サービス）
- URL：

銀行口座・証券口座・クレジットカードなどを自動連携し、資産状況をまとめて把握できる。
---

### 5-2. それでも自分が作りたい理由

既存サービスがある中で、

- なぜ満足できなかったのか
  - 既存の資産管理アプリは銀行や証券口座との連携が前提になっているが、連携の安定性に課題があり、思うように資産管理ができない場面が多かった。
特に楽天銀行など、一部の金融機関との相性が悪く、日常的に使うにはストレスを感じることがあった。
- どこに違和感があったのか
  - 既存サービスは「現在の資産を管理すること」に最適化されており、
“投資を始める前の人が未来を試してみる” という体験がほとんど提供されていない。

### 5-3. 差別化を「体験価値」で表現する

このアプリは、【どんな人】の【どんな瞬間】を一番助けるアプリですか？
- 私のアプリの差別化ポイント：
  - 投資に興味はあるけれど、未来が想像できずに一歩踏み出せない人が、
「自分の資産が何年後にどう育つのか」を知りたくなった瞬間を助けるアプリ。

## 7. このアプリで実現すること

### MVPで作る機能
- ログイン機能
- 資産管理機機能  
現在の資産額を入力し、資産推移を把握できる。
- シュミレータ機能  
現在の資産と積立額から、将来の資産をグラフで可視化する。

### 本リリースで作る機能
- 資産の評価機能
- 1か月の収入出管理機能
- 文章のAIによるシミュレーション（自然言語で未来予測）  
「何年後までに家の頭金を貯めたい」や「月のコーヒー代〇円を投資に回した場合」などでシュミレートできるようにする
- 情報共有できる掲示板

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク： Ruby on Rails8.1
- DB： PostgreSQL
- デプロイ先： render
- 使用予定ライブラリ： geminiAPI

---

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| React | 採用 | コンポーネント設計を学びたい＋操作性に優れたアプリにするため |
| Ruby on Rails | 採用 | 学習コストは低く、Reactとの相性〇 |
| PostgreSQL | 採用 | モダンなSQLでrenderとの相性〇。慣れているため学習コスト低 |

- 今回チャレンジしたい点  
React + railsAPIモードによる開発を行いたい。

- 不安な点と対策  
React を用いた開発経験が浅く、学習に時間がかかる可能性がある。
特に、Rails API と React の連携部分や、状態管理・コンポーネント設計でつまずく懸念がある。
対策として、Vite を用いた Rails + React のテンプレートプロジェクトを使い、
最小構成で React の開発体験を掴むところから始める。
