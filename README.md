## 1. サービス概要

- サービス概要
  - 資産管理＋シミュレーターアプリ
  - 過去と現在の資産を一元管理し、推移を把握できる
  - 現在の資産から、投資や積立を行った場合の将来資産を可視化する

- サービスが提供する価値
  - 「投資しても将来どうなるかわからない」という不安を解消し、自分の資産が何年後にどのように成長するかを可視化することで、投資行動を後押しするアプリ
  
    

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情
投資を始めようと考え、投資周りの情報を調べ始めた時、投資そのものに興味を持てるような“ワクワクする情報”がほとんど存在しないと感じた。  
存在するサイトは、超初心者向けの「積立だけを紹介するサイト」と、中級者以上向けの「株価要因を深掘りするサイト」の両極端しかなかった。

この経験から投資自体に興味を持てるサイトを作りたいと考えました。

---

### 2-2. なぜそれが「気になった」のか
投資は「難しそう」「自分には関係ない」と感じた瞬間に、興味を失ってしまう人が多い。  
情報は溢れているのに、投資そのものを“面白い”“やってみたい”と思える入り口がほとんど存在していない。
だからこそ、投資をもっと身近に感じられる体験が必要だと考えた。

---

## 3. 課題の整理

### 3-1. 表に見えている困りごと
投資を始めようとしても、「実際に何年後に資産がどう増えるのか」という未来のイメージが掴めないままでは、一歩を踏み出しづらい。

---

### 3-2. 本当に解決したい課題は何か

投資の未来を具体的に思い描けるようにし、投資そのものに興味を持てる状態をつくる。投資で未来がどう変わるか見えない状態では、「損をしたらどうしよう」、「投資したところで何も変わらない」といった漠然なイメージが存在し、投資を始められない人が多くいる。
投資でどのような資産の推移になるか未来の資産が「視覚的に理解できる」「自分の行動で変化する」と感じられることで、投資が難しいものではなく、身近で前向きな選択肢になる。

---

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

  - 生活・状況:

  - 理由：

---

### 4-2. 自分とユーザーの距離
- 過去の自分

投資を始める前の人や投資を詳しく勉強をしたことがない人を想定しているため。
また、私自身投資を始めるにあたり、どんな投資をすればよいかの目標があやふやで足踏みしていた経験があるため。
日本には投資経験のない人や投資知識に不安を感じている人が多いため、こうした層に利用してもらうことで、アプリの価値や改善点を検証していきたい。

- 検証方法
  - 投資に詳しくない友達2~3人に使用してもらう。  
  - 評価観点は以下
    - 使っていて楽しいアプリであったか。
    - 操作は難しかったか
    - また使ってみたいと思えたか



### 4-3. 実際に使われる可能性について

- まず最初に使ってくれそうな人は誰か？  
投資初学者
- その人は、どんな場面でこのアプリを思い出すか？  
「投資を始めたら、実際にどれくらい資産が増えるのか知りたい」と感じた瞬間。
現在の株価上昇率や積立額から、自分の目標額（例：家の頭金など）に到達するまでの未来をシミュレーションしたくなった時。
- 今の生活の中で、代わりに使っているものは何か？
  - 証券会社のシミュレーター
  - 資産管理アプリ
- それを置き換えてまで使う理由はあるか？
  - 既存のシミュレーターと資産管理アプリは基本的に独立しており、「自分の資産を起点にした未来シミュレーション」がしづらい。
  - 銀行口座や証券口座との連携が不要で、投資初学者でも“気軽に未来を試せる”点が強み。
（投資初学者はそもそも口座を開設していないケースが多く、既存アプリよりも使い始めやすい。）


## 4-4. ユーザーがサービスを導入して利用するまでのイメージ

- どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか  
証券口座をまだ持っていない投資初学者が、“気軽に未来を試してみたい” と感じた時に最も強く必要とされる。
また、「家の頭金まであとどれくらい必要なんだろう？」
等、未来のイメージが掴めずに不安を感じた瞬間に、このサービスを思い出す。

- 最初の一歩（登録・導入）で、ユーザーは何をする必要があるか  
現在の資産額や積立予定額をざっくり入力するだけ。

- 利用を続ける理由は何か？
未来の資産が“自分の行動で変化する”ことが実感できる。投資を“難しいもの”ではなく“育てる楽しさがあるもの”に変える体験が得られる。  
さらに、シミュレーターの利用を継続することで、ユーザーが入力した資産額データが時系列で蓄積される。これにより、過去から現在までの資産の変化や成長を可視化でき、自身の資産形成が着実に進んでいることを実感できる。
結果として、将来への見通しが持ちやすくなり、中長期的な資産管理や投資継続へのモチベーション向上につながる。

- どんなことができるか：

---

### 5-2. それでも自分が作りたい理由

- なぜ満足できなかったのか
  - 既存の資産管理アプリは銀行や証券口座との連携が前提になっているが、連携の安定性に課題があり、思うように資産管理ができない場面が多かった。
特に楽天銀行など、一部の金融機関との相性が悪く、日常的に使うにはストレスを感じることがあった。
- どこに違和感があったのか
  - 既存サービスは「現在の資産を管理すること」に最適化されており、“投資を始める前の人が未来を試してみる”という体験がほとんど提供されていない。私が求めていたのは資産の記録ではなく、自分の将来目標から逆算して投資計画を考えられる仕組みだった。しかし、そのような「将来のシミュレーション」を中心としたサービスは少なく、物足りなさを感じていた。


### 5-3. 既存アプリとの差別化ポイント

  - 投資に興味はあるけれど、未来が想像できずに一歩踏み出せない人が、「自分の資産が何年後にどう育つのか」を知りたくなった瞬間を助けるアプリ。

## 7. このアプリで実現すること

### MVPで作る機能
下記に示す機能を作成する。資産管理アプリシミュレーターは単独としては存在するが、組み合わせることにより、このアプリならではの「過去、現在、未来の状態を可視化する」アプリを作成する。


- ログイン機能
- 資産管理機能  
  - 月単位での資産管理
  - シミュレーションを行った月は、最後のシミュレーションで使われた資産額が自動反映
  - 後から手入力により修正、追加が可能

- シミュレーター機能  
現在の資産額、シュミレーションの年月（20年間T等）、月の積み立て予定額、株の想定上昇率を入力。

### 本リリースで作る機能
- シミュレーション機能にリスク度の追加
- 1か月の収支管理機能(資産管理機能の強化)
- Reactの導入
## 8. このアプリの懸念点とその対策

### 懸念点➀

- 何が問題になりそうか：  
実装までたどり着けない可能性がある
- なぜそう思うか：  
作成したい機能が多く、中途半端に終わってしまう可能性がある
- そのために考えている対策：  
MVPで作成する機能を制限して、「動くアプリ」をいち早く作成する。

### 懸念点➁
- 何が問題になりそうか：  
確実に利益が出るものだと思われてしまう。
- なぜそう思うか：  
世界株価は一定の割合で上昇しているため、シミュレーション上も上昇するように見えるが、実際は、リーマンショックやコロナなどで一時的に大きく落ちることがあるため。
- そのために考えている対策：  
注意文言を入れる。発展機能としてではあるが、リスク度まで踏まえたシミュレーションを提供する。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク： Ruby on Rails8.1
- DB： PostgreSQL
- デプロイ先： render
- 使用予定ライブラリ： Devise JWT（ログイン機能）、geminiAPI（発展機能）

---

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| React | 保留 | コンポーネント設計を学びたい＋操作性に優れたアプリにするため。本リリースで採用 |
| Ruby on Rails | 採用 | 学習コストは低く、Reactとの相性〇 |
| PostgreSQL | 採用 | モダンなSQLでrenderとの相性〇。慣れているため学習コスト低 |

- 今回チャレンジしたい点  
React + railsAPIモードによる開発を行いたい。

- 不安な点と対策  
React を用いた開発経験が浅く、学習に時間がかかる可能性がある。
特に、Rails API と React の連携部分や、状態管理・コンポーネント設計でつまずく懸念がある。
対策として、React実装を後続フェーズとし、まずはMVPの完成・リリースを目指す
